- abrir dois terminais
- no primeiro rodar o comando que inicia a aplicação em ejs
    npm run dev

- no segundo, a API de tradução (Python 3.11, o mesmo do Dockerfile.python).
  Com Python 3.12+ o spaCy 3.7 não instala.

  Primeira vez (cria a venv e instala as dependências; é o processo mais demorado):
    Linux/Mac:
      python3.11 -m venv venv
      source venv/bin/activate
      pip install -r requirements_api.txt
    Windows (PowerShell):
      py -3.11 -m venv venv
      .\venv\Scripts\Activate.ps1
      pip install -r requirements_api.txt
    (no Windows, o torch precisa do "Microsoft Visual C++ Redistributable":
     winget install Microsoft.VCRedist.2015+.x64)

  Nas próximas vezes, só ativar a venv e iniciar a API (ela lê os dados do banco do .env):
    Linux/Mac:
      source venv/bin/activate
      python3 ApiTradu.py
    Windows (PowerShell):
      .\venv\Scripts\Activate.ps1
      python ApiTradu.py

  Variáveis opcionais da API (todas têm valor padrão; podem ir no .env):
    MODELO_SPACY          modelo de gramática (padrão: pt_core_news_md)
    MODELO_EMBEDDING      busca por semelhança de significado (padrão: nenhum = desligada).
                          Se for ligar, use rufimelo/bert-large-portuguese-cased-sts: foi o único
                          de 6 modelos testados que acha sinônimos sem errar (cão -> CACHORRO).
                          Custa ~1,3 GB de download e ~1,5 GB de memória; os outros trocam
                          palavras com nota alta (sim -> ANO, brincar -> BRINCO).
                          Comparação: python scripts/avaliar_modelos_semanticos.py
    LIMIAR_SEMANTICO      nota mínima dessa busca, se ligada (padrão 0.90; abaixo de ~0.80
                          aparecem antônimos: magro -> GORDO)
    DATILOLOGIA           1 = soletra nomes próprios sem sinal (padrão), 0 = desliga
    REGISTRAR_SEM_SINAL   1 = conta palavras sem sinal na tabela termos_sem_sinal (padrão)
    CACHE_TTL_SEGUNDOS    a cada quanto tempo recarrega os sinais do banco (padrão: 3600;
                          mudanças feitas pela administração já recarregam na hora)
    TOKEN_INTERNO         liga as rotas internas usadas pela administração (mesmo valor do site)
    S3_BUCKETS            buckets lidos pela importação (padrão: words-traducao,tradulibras-videos)
    AWS_REGION            região dos buckets (padrão: us-east-1)
    API_PORT              porta da API (padrão: 5000)

- área de administração (http://localhost:3000/admin):
  1. No .env (o mesmo arquivo serve para o site e para a API), defina TOKEN_INTERNO com um texto
     aleatório e reinicie os dois. Para gerar:
       node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  2. Cadastre-se no site (/register) e transforme a sua conta em administrador:
       node scripts/tornar-admin.js seu@email.com
  3. Entre pelo /login normal: o administrador cai direto em /admin.
  As tabelas novas (planos, cursos, importação do S3, registro) são criadas sozinhas quando o Node sobe.
  Para "Importar do S3" funcionar, a API precisa de credenciais da AWS com permissão de listar os
  buckets (AWS_ACCESS_KEY_ID e AWS_SECRET_ACCESS_KEY no .env, ou ~/.aws/credentials). Sem elas, o
  resto da administração funciona e a tela do S3 mostra o aviso.

- medir a qualidade da tradução (rode depois de mexer no tradutor ou no banco de sinais):
    python scripts/avaliar_traducao.py --detalhes
  O número mais importante é "sinais ERRADOS": um sinal errado é pior do que nenhum sinal.
